## What's in 1.1.0

Version `1.1.0` is here because I actually tried running real queries against the full galaxy database, realized a bunch of things were on fire (or running at the speed of molasses), and had to fix my own dumb mistakes.

Here is the honest breakdown:

### 1. Spatial Queries: Stop Accidentally DDOSing Postgres

If you ran some of the previous spatial queries across 400M systems, you probably noticed Postgres pegged at 100% CPU contemplating its life choices. They were doing unindexed galaxy-wide Cartesian joins.

* Anchored spatial trade runs, mining havens, and neutron star clusters to a reference system using 3D GiST bounding boxes (`cube_enlarge`), chopping the search down to the local cluster first.
* Swapped out $O(N^2)$ all-pairs distance loops with `CROSS JOIN LATERAL` nearest-neighbor KNN scans (`<->`).
* Pushed `ORDER BY ... LIMIT` deep into subqueries so Postgres stops joining millions of rows it immediately tosses into the void. Queries now return in milliseconds instead of minutes.

### 2. Ring Hotspots: The "I Forgot How JSON Works" Fix

I had a classic late-night moment where `JournalScanTransformer` was double-wrapping ring signals into nested `{"signals": {...}}` JSON objects even though `update_dtm` was already sitting right on the table row.

* Flattened `body_rings.signals` to clean key-value pairs (`{"Platinum": 3, "Void Opal": 1}`).
* Mapped raw Frontier commodity tokens (`$Opal_Name;`, `LowTemperatureDiamond`) directly to canonical commodity names so miners can actually find their Void Opals.
* Swapped the GIN index on `body_rings.signals` (`idx_body_rings_signals`) to index the root JSONB directly instead of using a JSON path expression.

### 3. Engineers: Finding Where Palin and Chloe Are Hiding

I was tired of hardcoding engineer systems.

* Added `17_engineers.sql` and `db_setup/data/engineers.yaml` covering all 38 engineers across the galaxy (25 Horizons Ship and 13 Odyssey On-Foot workshops) with specialties, max grades, unlock requirements, permit flags, and coordinates.
* Added `DataSeeder` (`db_setup --action seed`) to automatically discover, validate, and bulk upsert reference YAML files into Postgres so we never have to manually write monolithic seed SQL again.

### 4. `db_setup`: Making Setup Not Suck

The database setup tool got an overhaul so you don't have to fight it:

* Standardized the setup CLI as `db_setup` with console entrypoints in `pyproject.toml`.
* Fixed credential precedence: environment variables $\to$ CLI flags $\to$ interactive TTY prompts $\to$ auto-generation.
* Fixed the docs on `--action all` (fresh install with inline constraints) vs `--action rebuild-constraints` / `--action rebuild-indexes` (strictly for post-bulk recovery).

### 5. Extra Indexes & Exploration Sanity

* Added targeted partial and GIN indexes so the query planner stops choosing violence on powers, gravity, ring density, biological genuses, modules, and station services.
* Taught the router to treat client-side procedural `POIScene_` surface signals as `GenericPOI` instead of screaming about unmapped tokens in the error log.

### 6. Automated Releases & CI Upgrades

* Added `.github/workflows/release.yml` so pushing a version tag (e.g. `v1.1.0`) builds distribution wheels and publishes the GitHub Release with these release notes attached automatically.
* Added `.gitattributes` to enforce consistent Unix LF line endings repo-wide and added license immutability verification in CI.
